# Loop 1 plan: the core

The ordered work list for the first build loop ([build plan](../../docs/design/build-plan.md)). One item per iteration, in order; the loop checks items off and the host stops when every item is checked and `scripts/ralph/check.sh --strict` passes. Each item names the docs that define it and what "done" means. The docs are the spec; this file only orders the work.

Package layout, from [module-map.md](../../docs/design/module-map.md): `cmd/tess` (just `os.Exit(cli.Main())`), `internal/cli` (adapter: cobra commands, flags, JSON and human output), `internal/tracker` (all behaviour, the `Tracker` interface), `internal/ids` (pure), `internal/store/sqlite` (schema, views, transactions, events). No `sync` package in loop 1.

## Items

- [ ] 1. SQLite store: schema, views, transactions. `internal/store/sqlite`. Open or create the database file named in [cli.md](../../docs/design/cli.md) (`init`), WAL mode, `BEGIN IMMEDIATE` with busy retry ([ADR-0003](../../docs/adr/0003-global-issues-in-git-common-dir.md), [ADR-0006](../../docs/adr/0006-ncruces-sqlite-driver.md); don't import the driver's `embed` package). Tables: `issues` (texts held as hashes), `texts(hash, body)` ([ADR-0014](../../docs/adr/0014-content-addressed-text.md)), `labels`, `links` (one row per link, canonical direction, [ADR-0015](../../docs/adr/0015-four-link-types.md)), `comments`, `events` ([ADR-0013](../../docs/adr/0013-field-level-event-log.md)), `config` (prefix, schema version). Views: `live_issues` ([ADR-0010](../../docs/adr/0010-retire-instead-of-delete.md)), readiness edges, `blocked_issues` ([ADR-0007](../../docs/adr/0007-readiness-is-one-sql-view.md), [ADR-0016](../../docs/adr/0016-hierarchy-rules.md); recursion guard ~100), and a view or query for "has open children". Done when unit tests against `:memory:` cover: a direct active blocker; a `done`/`omit`/retired blocker not blocking; a blocked ancestor and a `held` ancestor blocking a grandchild; open children not making the parent blocked; and two connections writing concurrently without a `SQLITE_BUSY` surfacing.
- [ ] 2. IDs. `internal/ids`: generate `<prefix>-<base36>` from a SHA-256 over prefix, title, creator, created_at and a nonce, with the length adaptive to the issue count and at least 3 characters ([ADR-0017](../../docs/adr/0017-flat-immutable-ids.md); the old tool's `internal/idgen/hash.go` and `adaptive_length.go` are the reference); collision handling inside the create transaction. Resolution rules as pure logic over candidates the store supplies: exact, then unique prefix, then unique substring, never matching retired issues, `ambiguous_id` listing the candidates, `not_found` otherwise ([requirements.md](../../docs/requirements.md), [README](../../acceptance/README.md) "Retired issues" and "ID shape"). Imported IDs like `bd-abc.1` must still resolve exactly. Done when unit tests cover generation shape, adaptive length, collision, and every resolution rule.
- [ ] 3. Tracker: create, get, update. `internal/tracker` with the `Tracker` interface from the module map, a clock and an actor passed in (no globals). `Create` allocates the ID in the transaction, stores texts by hash, labels, `--parent` and `--blocked-by` links. `Get` resolves a partial ID and returns the full issue object of the [README](../../acceptance/README.md): displayed status (`waiting` for a stored `ready` that is blocked or has open children), `blocked`, `ancestors` nearest first, sorted `labels`, `links.*` omitting retired issues, `comments`, `previous_status` for a held issue (from events), and `history` on request. `Update` takes a typed `Patch`; the store diffs it into events in the same transaction (only changed fields; `updated_at` never; text fields log hashes; labels one element per event); clearing optional fields; `retired` refused. Done when unit tests cover these through the interface, including event contents.
- [ ] 4. Tracker: status. `Status(ids, status, reason, force)` per [ADR-0018](../../docs/adr/0018-one-status-command.md) and [ADR-0009](../../docs/adr/0009-status-model.md): `invalid_status` (incl. `waiting`), `reason_required`, `invalid_transition`, `has_open_children`, `blocked` unless force, no side effects on other fields, several IDs at once, and `newly_unblocked` computed as the set difference of `blocked_issues` before and after the change, inside the transaction. Done when unit tests cover every code and the unblocking of a dependent by `done` and by `omit`.
- [ ] 5. Tracker: links, cycles, tree. `Link`/`Unlink` accept all wordings in [cli.md](../../docs/design/cli.md) and normalise to the canonical stored direction; adding an existing link in either wording is a no-op success returning the existing link; `related` is symmetric; cycle detection over `blocks` and `parent` only, including self-links; `has_parent`; events logged once on the dependent or child side ([README](../../acceptance/README.md) "Event attribute names"); `parent` logs `null → P` and `P → null`. A `Tree` query returning the nested `{"id","title","status","children","blocked_by"}` nodes. Done when unit tests cover each wording, idempotence, every cycle shape, and the event sides.
- [ ] 6. Tracker: retire, restore, comments, list. `Retire` (sets `retired_at`, reason, returns `newly_unblocked`), `Restore` (exact ID only), `Comment` (immutable, author from the actor). `List(Filter)` with status (displayed status), type, label, assignee, parent (descendants), blocked, retired, all, search (case-insensitive substring over title, description, notes), limit; `ready` is `List` with the ready filter; ordering priority, then `created_at`, then `id` ([README](../../acceptance/README.md) "Command results"). Done when unit tests cover each filter, the ordering, and that retired issues are absent everywhere except `--retired` and exact-ID `Get`.
- [ ] 7. CLI framework, init, orientation, sync stub. `internal/cli` on cobra: `cli.Main()`; global `--json`; the error envelope `{"error": {"code","message","hint"}}` on stderr with exit 1, and `error: ...` in plain mode; unknown commands and flags, bad flag values, and a missing title become `invalid_argument`; `not_a_git_repo`, `not_initialized` (plain message mentions `tess init`), `already_initialized`. `TESS_NOW` clock seam and actor detection ([README](../../acceptance/README.md) "What the binary must provide", [ADR-0019](../../docs/adr/0019-agent-context-integration.md) item 2). `tess init [--prefix]` with the database under the git common dir and `database` absolute in JSON; prefix defaults to the repo directory name. `tess` with no arguments prints ~10 lines naming `tess ready`, `tess create`, `tess status`, `tess sync`. `tess sync` exits 0 and prints `sync: not available yet` to stderr. Done when `init` passes and the first half of `cli` (orientation, error shapes, unknown command/flag) does.
- [ ] 8. CLI: create, show, update, status, retire, restore, comment. Every flag in [cli.md](../../docs/design/cli.md); text flags take `-` for stdin, verbatim; `--due` accepts `YYYY-MM-DD` or RFC 3339; `show` accepts several IDs and `--history`; `status` and `retire` print `{"updated","newly_unblocked"}`; plain `create` prints the ID. Done when `create_show`, `update`, `status`, `retire`, `history`, and `readiness` pass.
- [ ] 9. CLI: link, unlink, tree. All wordings; JSON `{"from","type","to"}` in canonical direction; `tree` plain output lists the neighbourhood's IDs. Done when `links` and `hierarchy` pass.
- [ ] 10. CLI: list and ready output. Filters and `-n`; JSON is a flat array in display order; plain output is flat when stdout isn't a TTY (`<symbol> <id> <title>` per line, symbols from [cli.md](../../docs/design/cli.md), no colour unless a TTY); `--tree` shows ancestors as headers and indents results; `--flat` forces flat on a TTY; `-n` counts results, not headers. Done when `list` passes.
- [ ] 11. Import from bd. `tess import PATH` per the [README](../../acceptance/README.md) "Import reasons" and "Import keeps original IDs": status, reason, link-type and tombstone mapping, comments, labels, timestamps and `created_by` carried over, all-or-nothing with a cycle check, re-import skips existing IDs. Done when `import` passes.
- [ ] 12. Agent integration: `setup claude` and `hook`. Per [ADR-0019](../../docs/adr/0019-agent-context-integration.md) and the hook details in [cli.md](../../docs/design/cli.md): write `.claude/skills/tess/SKILL.md` (frontmatter `name: tess`, a ~300-character `description`, `allowed-tools: Bash(tess *)`; a 40–60 line body with the work loop, the JSON fields, and "run `tess sync` when you finish a unit of work") and merge into `.claude/settings.json` without disturbing other keys: a `Bash(tess *)` allow rule, a `SessionStart` group and a `SessionEnd` group calling `tess hook ...`. Re-running writes nothing and reports `"written": []`; `--check` exits 1 when anything is missing or stale; `--remove` takes out only what tess added. `tess hook session-start` reads the hook JSON on stdin, skips the sync when `source` is `compact` (and in loop 1 always, since sync is a stub), prints 3–6 lines of facts and nothing when there's no database, exit 0 always; `tess hook session-end` exits 0 at once in loop 1. Done when `setup_claude` passes.
- [ ] 13. Help with examples on every command. Each command's `--help` has an `Examples` section with real invocations; `status --help` lists the settable values; `link --help` shows the inverse wordings. Done when `cli` passes in full.
- [ ] 14. Suite green. `scripts/ralph/check.sh --strict` ends with `=== ALL CHECKS PASS`: every acceptance script passes, no unit test skips, `gofmt` clean. Fix whatever remains, without touching `acceptance/`. Then read through `internal/` once for anything that contradicts an ADR or duplicates a code path, and fix it.

## Notes

Iterations append here, newest at the bottom, under a heading `### Item N`. Human-facing: decisions, deviations, gotchas, what to look at by hand.

### Reflections

One `- Item N:` bullet group per iteration. Where the docs or suite were ambiguous or felt wrong and how it was resolved, anything done without confidence, and friction with the prompt, plan, sandbox, or checks. The human reads these to decide what to look at later.

### Discovered

Work found outside the current item, one line each, for the human to triage.
