# Loop 2 plan: sync

The ordered work list for the second build loop ([build plan](../../docs/design/build-plan.md), [sync.md](../../docs/design/sync.md)). One item per iteration, in order; the loop checks items off and the host stops when every item is checked and `scripts/ralph/check.sh --strict` passes. Each item names the docs that define it and what "done" means. The docs are the spec; this file only orders the work. Loop 1's plan and notes are in [plan-loop1.md](plan-loop1.md).

Package layout, from [module-map.md](../../docs/design/module-map.md): `internal/git` (runs the git binary), `internal/sync` (snapshot, merge, store, `Run`; the exported API in `sync.go` is fixed by [acceptance/README.md](../../acceptance/README.md) "The simulator"), `internal/sync/gitref` (the transport, the only place that knows ref names), and `internal/cli` for `sync`, `doctor` and the hooks.

## Items

- [ ] 1. Git plumbing. `internal/git`: run the user's `git` binary for what the transport needs ([sync.md](../../docs/design/sync.md) "Git", [ADR-0020](../../docs/adr/0020-v1-dependencies.md)): `rev-parse` (common dir, a ref's commit, whether a ref exists), the remotes and their URLs, `fetch` of one refspec into a local ref, `push` with `--force-with-lease=<ref>:<expected>`, `update-ref` with the expected old value, `ls-tree -r` of a commit, `cat-file --batch` for many blobs in one process, and writing a whole tree and commit in one process (`fast-import`, or `hash-object --stdin-paths`/`mktree`/`commit-tree` if fast-import proves awkward; say which in the notes). Author, committer and dates come from arguments, never from the environment. Errors are classified: the remote unreachable (`offline`), a non-fast-forward rejection (retryable), any other rejection (`push_rejected` with git's reason), with the stable codes as `*tracker.Error`. Move the `rev-parse` helpers of `internal/cli/env.go` here and make `cli` call them. Done when unit tests against bare repositories under `$TMPDIR` cover each operation, a rejected push from a `pre-receive` hook, a non-fast-forward push after the remote moved, and an unreachable remote path.
- [ ] 2. Snapshot. `internal/sync`: the `Snapshot` types as exported, `Files()` with the canonical encoding of [sync.md](../../docs/design/sync.md) "The snapshot" (key order, no whitespace, one trailing newline, RFC 3339 UTC seconds, texts by hash with bodies under `texts/`, each link on the issue whose event log records it, `related` on the smaller ID, collections sorted, `config.json` with `format` and `prefix`), a `FromFiles` that parses the tree back, and `Load` from a database (stored status, never `waiting`; every issue including retired ones; all comments, events and texts). Done when unit tests show `Files()` → `FromFiles` → `Files()` is the identity, two databases that reach the same state by different operation orders give identical files, and `Load` of a database built through the tracker holds what the tracker shows.
- [ ] 3. Merge. `Merge(lkg, ours, theirs)` per [sync.md](../../docs/design/sync.md) "The merge" and [ADR-0021](../../docs/adr/0021-latest-event-wins.md): which issues (new, same-issue-twice by `created_at` and `created_by`, the ID collision as `conflict`, the retired-record exception of [ADR-0023](../../docs/adr/0023-id-collisions-refuse.md)); the units; the latest-event rule with its tie-breaks; `updated_at` as the later; the retire rule; events and comments as the union; `prefix_mismatch` and `format_unsupported`; resolutions with `won` and `reason`. Pure: no clock, no environment, no database, and symmetric in ours and theirs. Done when unit tests cover every rule in that section with snapshots built in memory, including change-and-change-back, remove-then-add of a label, an edit after and before a retire, no-event fallbacks, and symmetry (`Merge(l, a, b)` and `Merge(l, b, a)` give identical files and the same resolutions with `won` flipped).
- [ ] 4. Structure after the merge. [ADR-0022](../../docs/adr/0022-merge-repairs-structure.md): after the field merge, check the hierarchy rules of [ADR-0016](../../docs/adr/0016-hierarchy-rules.md) over all issues including retired ones; drop the latest-event link among the new links in a violation, report it with reason `cycle`, repeat until clean. Done when unit tests cover a two-link loop, a longer loop, a `blocks` link against a `parent` link where the parent link is the later one, a `blocks` link into a grandchild, and a merge needing two rounds of dropping.
- [ ] 5. Writing a merged snapshot. `internal/sync` (with whatever the store needs in `internal/store/sqlite`): write a merged snapshot into the database in one `BEGIN IMMEDIATE` transaction, replacing each changed issue's row, labels and links, adding new comments, events and texts, logging no events ([sync.md](../../docs/design/sync.md) "Writing the merged snapshot"); set `sync.last_at` and `sync.last_result`. Done when unit tests show `Load` after the write equals the merged snapshot, an unchanged issue's row is untouched, and the readiness views agree with the written links.
- [ ] 6. Transport and `Run`. `internal/sync/gitref` and `Run` in `internal/sync`: the local ref `refs/tess/sync` and the fetched ref; reading a snapshot from a commit; writing one as a commit with the LKG and theirs as parents; the full sequence of [sync.md](../../docs/design/sync.md) "What a sync is" with the push before any local write, `--force-with-lease`, three attempts in all on non-fast-forward (sync.md: "three times at most"), compare-and-swap on the local ref, the lock file and `busy`, `no_remote` and the remote choice, `offline`, `--dry-run`, `Fetched`/`Pushed` counts. Done when `go test ./acceptance/sim/ -run TestScenarios` passes in full and unit tests cover the retry (a remote moved between fetch and push, done with a `pre-receive` hook or a second copy), the lock, and that a failed push leaves the database and the local ref untouched.
- [ ] 7. CLI `tess sync`. `internal/cli`: `tess sync [--remote NAME] [--dry-run]` with the plain output and JSON of the [README](../../acceptance/README.md) "Sync output" (resolutions on stderr, summary on stdout; `up to date`; `would push N`), the codes as command errors, the orientation line, `--help` with examples. Add `KeptAt` and `DroppedAt` to `Resolution` as the README gives them (filled by the merge; the plain output prints them, JSON has `kept_at`/`dropped_at`). Remove the loop-1 stub. Done when `init` and `sync` pass except the hook steps at the end of `sync.txtar` (item 10), and `cli` fails only on `tess doctor`.
- [ ] 8. The simulator green. `TESS_SIM_RUNS=100 go test -count=1 ./acceptance/sim/` passes. Fix what it finds in the merge, the structure check, the store write or the transport; add a unit test for each fix. If a random run fails on something you believe is the invariant's mistake, abort and say which seed and which line of `invariants_test.go`. Done when the full run passes and `check.sh --strict` reports every scenario and random run passing.
- [ ] 9. `tess doctor`. [sync.md](../../docs/design/sync.md) "Command surface" and the [README](../../acceptance/README.md) "Doctor output": the eight checks in order, the four levels, the `fix:` lines, the JSON array, exit 1 only on `fail`, `--remote`, the other-tracker check over the repo's and the user's Claude settings and `.beads/`, reading nothing else. In the orientation, with examples in `--help`. Done when `doctor` and `cli` pass.
- [ ] 10. Hooks. `tess hook session-start` runs the sync in-process with a ten-second deadline unless `source` is `compact`, and prints the `Last sync` fact of the [README](../../acceptance/README.md) "Hooks" (`just now`, `never`, `not synced (<code>)`, `<when>, not synced now (<code>)`), never failing and never writing to stderr; `tess hook session-end` starts `tess sync` detached with output discarded and exits at once. Update `internal/cli/skill.md` (the work loop's "run `tess sync`" line stays; mention `tess doctor` under finding things) and the hook help. Done when `sync` passes in full and `setup_claude` still passes.
- [ ] 11. Suite green and a read-through. `scripts/ralph/check.sh --strict` ends with `=== ALL CHECKS PASS`. Then read `internal/sync`, `internal/sync/gitref` and `internal/git` once for anything that contradicts an ADR, reads the environment where it shouldn't, runs one git process per object, or duplicates a code path, and fix it. Done when strict passes.
